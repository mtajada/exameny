# Exameny v0.1.0 release candidate

These notes describe the candidate for Exameny's first public release: the full
public application for learners, teachers, and language academies, rebuilt as a
clean open-source edition. They become release notes only after the public gates
pass and the maintainer approves the exact commit and tag.

## Highlights

- Original writing, reading, language-use, coaching, and speaking practice.
- Learner progress, teacher assignment, academy membership, and platform flows.
- A static local demo that needs no account, cloud project, or API key.
- A reproducible Supabase schema, RLS policies, RPCs, and synthetic seed.
- `gpt-5.6-luna` through the Responses API with strict outputs and `store: false`.
- Reviewed model evidence: 22/24 cases, 8/8 adversarial safety checks, 24/24
  structured outputs, p95 6.32 seconds, and USD 0.0099058 measured cost.
- Workflows for CI, dependency updates, code scanning, secret scanning, license
  review, and SBOM generation, pending their first public run.

The model report retains four superseded or failed attempts and two remaining
pedagogical classification disagreements.
See [`evals/luna/evidence/live-evaluation.md`](../../evals/luna/evidence/live-evaluation.md).

## Try the no-service demo

```sh
npm ci --ignore-scripts
cp .env.example .env.local
npm run dev -- --host 127.0.0.1 --port 8080
```

Open `http://127.0.0.1:8080/demo`.

## Trust and provenance

The candidate starts with a clean Git history. It contains synthetic data and
original clean-room
educational content; it does not contain production records, private service
bindings, private documents, or examination-provider material. History scanning
passed against that history. Exameny is independent and does not claim official
scoring or certification.

## Known limitations

- Miguel Tajada Ferrer currently reviews changes and release candidates as the
  sole maintainer.
- AI feedback needs human judgement and does not replace a teacher.
- The model suite is deliberately small and synthetic.
- The authenticated stack requires the Supabase CLI and a Docker-compatible
  runtime; the static demo does not.
